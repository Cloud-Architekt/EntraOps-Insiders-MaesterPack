# Contributing to the EntraOps Maester Pack

This repository is private: contributions come from people with access, through its issues and pull requests. For defects, include the pack version, the
EntraOps version that wrote `findings.json`, the Maester and PowerShell versions, the sanitized test result and
the steps to reproduce it. Do not include tenant secrets, access tokens, unredacted `findings.json` files or
other sensitive tenant data.

## Where a change belongs

EntraOps evaluates the checks, and most of this repository is generated from the EntraOps finding rule catalog
by `Build-EntraOpsMaesterPack.ps1`. A change to a generated file here is overwritten by the next build, so it
belongs in EntraOps, in the [EntraOps Insiders repository](https://github.com/Cloud-Architekt/entraops-insiders) that the pack is generated from:

| Change | Where |
| --- | --- |
| What a check evaluates, its title, severity, description, remediation or thresholds | EntraOps: the finding rule catalog (`EntraOps/Private/Findings`) |
| How the pack reads `findings.json` and reports a result (`helpers/`) | EntraOps: `Integrations/Maester/Template/helpers` |
| `maester-pack.json`, `entraops-source.json`, `tests/` | EntraOps: generated by `Integrations/Maester/Build-EntraOpsMaesterPack.ps1` |
| The guide, banner, documentation, changelog, checks of the pack (`ci/`), tools and GitHub templates | This repository |

Published test IDs never change: Maester refuses an update of a pack whose tests change their meaning. A new
check is a new EntraOps rule at the end of its category, and a check that is no longer needed stays with
`Lifecycle` `Deprecated`.

## Before opening a pull request

- Search existing issues and pull requests before opening a new issue or proposing a duplicate change.
- Keep the change focused. The pack must stay valid and Low risk: keep `Uses` in `maester-pack.json` empty.
- Every `.ps1` file may contain function definitions only; Maester refuses the pack otherwise.
- Use synthetic data only in `ci/fixtures` (for example the tenant `00000000-0000-0000-0000-000000000000` and
  `contoso.onmicrosoft.com`).
- Run the checks of the pack. They need Pester and Maester 3.0 or later, but no tenant connection:

  ```powershell
  Invoke-Pester -Container (New-PesterContainer -ScriptBlock { . ./ci/PackChecks.ps1; Invoke-EntraOpsPackCheck })
  ```

- Update [CHANGELOG.md](./CHANGELOG.md) (the section of the next version) for user-facing changes, and
  [TESTS.md](./TESTS.md) when the tests change.
- Follow [SECURITY.md](./SECURITY.md) for vulnerabilities; do not disclose them in a pull request or issue.
